## Что сделано и что не успел

Список матчей с отдельной карточкой, скелетоном, фильтрами, обновлением, ошибкой с повтором и пустыми состояниями.
Подключено избранное, исправлен UpdatedAgo; новых зависимостей нет.
Добавлен поиск по названию команды: отдельный Input и useDebounce с задержкой 300 мс.

Исходный MATCHES_URL содержит OWNER/REPO и возвращает 404: для реальной загрузки нужен рабочий адрес.

## Решения

- «Предстоящие»: scheduled и postponed — перенесённый матч ещё предстоит сыграть. «Завершённые»: finished; остальные статусы — только во «Все». Фильтрация идёт по статусу, а не дате.
- Intl.DateTimeFormat без timeZone использует часовой пояс устройства. Для даты null показано «Дата и время уточняются», для отсутствующего счёта — прочерки; 0:0 сохраняется.
- Проверяются HTTP-статус и структура ответа, запрос отменяется при уходе с экрана. При ошибке обновления остаются предыдущие данные и время успешной загрузки; избранное хранится по id в памяти экрана.
- Поиск по хозяевам и гостям сочетается с фильтром статуса, не учитывает регистр, лишние пробелы и различие е/ё. При отсутствии совпадений показано «Ничего не найдено»; новые запросы на сервер не нужны.

## Баги из части 2

1. Звёздочки: Boolean(indexOf(id)) давал true для отсутствующего id (-1) и false для первого элемента (0), а push/splice меняли исходный массив — React мог пропустить перерисовку.
   Исправлено на includes и функциональное обновление с новым массивом; общее состояние передаётся карточкам и в extraData у FlatList.
2. «Обновлено N сек назад»: интервал захватывал начальное seconds и постоянно записывал 1, игнорировал since и не очищался.
   Теперь секунды вычисляются как разница Date.now() и since, а эффект перезапускает и очищает интервал при смене времени загрузки и размонтировании.
