# Решение

## Сколько заняло

Выполнено агентом в текущей сессии; ручное время не замерялось.

## Что сделано и что не успел

Загрузка из MATCHES_URL, отдельная карточка MatchCard, скелетон, ошибка с повтором,
пустые состояния, три фильтра и кнопка обновления. При ошибке обновления сохраняются
предыдущие данные и время последней успешной загрузки. Новые зависимости не нужны.
Использован существующий UpdatedAgo без изменений — по прямому указанию пользователя.
Звёздочки из части 2 README не входят в текущий запрос.

Проверки: `npx tsc --noEmit`, `npm test` (8 тестов: фильтры, валидация ответа,
нулевой счёт, статусы, часовые пояса и переход даты). В браузере проверены скелетон,
ошибка 404, карточки, оба фильтра, обновление и пустой список. Для успешного/пустого
ответа временно использовалась фикстура; исходный MATCHES_URL восстановлен.

## Решения

- «Предстоящие»: scheduled и postponed — перенесённый матч ещё предстоит сыграть,
  даже если новая дата неизвестна. «Завершённые»: только finished. live, отменённые
  и неизвестные статусы видны только во «Все»: они не подходят к двум другим категориям.
- Фильтрация основана на статусе сервера, а не на сравнении даты с текущим временем.
- Дата форматируется через Intl.DateTimeFormat('ru-RU') без заданного timeZone,
  то есть в часовом поясе устройства. Для startsAt: null показано «Дата и время уточняются».
- Нулевой счёт сохраняется через ??; при отсутствии счёта показаны прочерки.
  Статусы переведены на русский, для неизвестного — «Статус уточняется».
- Проверяются HTTP-статус и структура JSON, включая уникальность id. Ошибочный ответ
  не выдаётся за пустой список. Запрос отменяется при размонтировании, тайм-аут — 15 секунд,
  повторные нажатия не создают параллельные запросы.
- MATCHES_URL содержит OWNER/REPO. Адрес сохранён согласно src/config.ts;
  до появления рабочего endpoint приложение покажет ошибку с кнопкой «Повторить».

## Баги из части 2

1. Звёздочки: не изменялись, часть 2 не запрошена.
2. «Обновлено N сек назад»: UpdatedAgo захватывает начальное seconds в замыкании,
   поэтому интервал постоянно записывает 1; since не используется, интервал не очищается.
   По указанию пользователя компонент подключён без исправлений: после успешной загрузки
   передаётся новый since, но существующий счётчик по-прежнему застывает и не сбрасывается.

## Как я использовал ИИ

Реализация — Codex. Документация Expo SDK 57, React Native и React проверена через
Context7 и официальные сайты. Изменения внесены через apply_patch.
Отдельная замена UpdatedAgo была предложена агентом, но отклонена пользователем;
используется исходный компонент.

## Что улучшил бы, будь ещё 2 часа

После разрешения на изменения исправил бы UpdatedAgo: вычисление прошедших секунд
от since, сброс при его изменении и очистка интервала. Добавил бы интеграционные тесты
на сетевые состояния и проверил экран в Expo Go на iOS и Android.
